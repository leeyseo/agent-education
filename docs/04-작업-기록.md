# 작업 기록 (2026-10-26)

Claude Code 세션 하나에서 Google Flow 조사부터 숏츠 19편 완성까지 진행했다. 각 단계에서 무엇을 정했고 왜 그렇게 했는지 남긴다.

## 1. Google Flow 조사

교육 영상에 생성형 영상을 쓸 수 있는지 보려고 Flow를 먼저 조사했다.

- Flow는 Veo(영상), Nano Banana(이미지), Gemini Omni 모델을 한 화면에서 쓰는 구글의 웹 도구다. DeepMind 모델 페이지에는 모델만 있고 Flow는 나오지 않는다.
- 구독하지 않은 계정도 **하루 50크레딧**. 비용은 Veo 3.1 Lite 10, Fast 20, Quality 100 (무료로는 Quality 불가). Gemini Omni Flash 360p는 4~7.
- 남은 크레딧은 이월되지 않는다. UTC 오후 2~5시(한국 밤 11시~새벽 2시)에는 무료 계정이 영상을 못 만들 수 있고, 1080p 업스케일은 구독자만 된다.
- 만 18세 이상, 한국에서 사용 가능. 영어 프롬프트를 권장한다.
- 2026년 I/O에서 'Flow Agent'(기획·일괄 편집을 돕는 Gemini 조수)가 추가됐다.
- 결론: Flow는 열정이 캐릭터 컷이나 훅 장면에만 쓰고, 설명 화면은 직접 만든다.

출처: [Flow 크레딧 안내](https://support.google.com/flow/answer/16526234?hl=en), [Flow 이용 가능 국가](https://support.google.com/flow/answer/16353544), [Google DeepMind Gemini](https://deepmind.google/models/gemini/), [Fonearena: I/O 2026 Flow](https://www.fonearena.com/blog/483182/google-i-o-2026-google-flow-music-gemini-omni-ai-agents-mobile-apps.html)

## 2. 시리즈 기획

요청 내용: 대상 업체의 기존 작업 순서(회의 → 기획 PPT → 포토샵 → 마크업 → FTP)에서 에이전트를 어떻게 쓰는지, 레퍼런스는 사이트를 던지면 알아서 분석하는 것, 배포도 자연어로, 기획 결과물이 텍스트여도 된다는 것. 그리고 에이전트의 문제(시키지 않은 일까지 해서 5,000줄을 바꾸는 등)와, 그래서 사람이 의심하고 캐물으며 디렉팅해야 한다는 것.

- 핵심 비유를 '의욕 넘치는 천재 신입과 그 사수'로 정했다.
- 가상 제작사(픽셀공방)와 고객(모닝빵 베이커리) 하나로 전 편을 잇기로 했다.
- AI를 검색창으로만 아는 사람을 위해 1부를 늘렸다: 검색 vs 챗봇 vs 에이전트, 왜 좋은 모델이어야 하나(단계가 쌓이면 실수가 곱해짐: 95%×20단계 ≈ 36%), Claude 도구 지도(Cowork·Claude Design·Claude Code).
- 기획안은 Claude 문서로 정리했다: https://claude.ai/artifact/TJBvkPapd2qCr7hNCbR32t (개인 문서, 공유 권한 필요)

## 3. EP1 제작과 되돌리기

1. **첫 버전 (43초)**: HTML 애니메이션을 프레임 단위로 찍어 mp4로. 내레이션은 Windows 기본 한국어 음성(Heami).
2. **피드백: "훅이 없고 지루하다, 속도감이 떨어진다"** → 두 번째 버전(27.7초): 결과를 먼저 보여주는 훅 장면, 말 속도 2배, 단어 단위 자막, 장면 밀어 넣기, 효과음 78개와 비트 배경음악 합성.
3. **피드백: "너무 빠르다, 롤백하자"** → 첫 버전으로 되돌림. 두 번째 버전 코드는 `shorts/ep01/_v2/`에 남겼다(효과음·배경음악 합성 `sound.py` 포함).

배운 점: 이 대상에게는 빠른 편집보다 또박또박한 설명 속도가 맞다. 이후 모든 편은 첫 버전 속도를 기준으로 했다.

## 4. 내레이션 목소리 고르기

1. **"기계음 싫다"**: Windows 음성은 쓰지 않기로 했다.
2. **참고 영상 분석**: 사용자가 준 숏츠 광고(명함 디자인 업체, 영화 장면 위 다큐 해설 톤)의 목소리 높낮이를 쟀다. 내레이터는 남성, 중앙값 약 130Hz, 폭 85~190Hz.
3. **무료 신경망 음성 비교**(edge-tts): 인준, 현수, 선희로 샘플을 만들었다. 현수(차분하게)가 130Hz로 가장 가까웠다.
4. **ElevenLabs로 결정**: Rachel을 원했지만 무료 플랜에서 Voice Library 목소리는 API로 쓸 수 없어(402) **Brian**으로 정했다. Brian은 중앙값 123Hz, 폭 80~195Hz로 참고 영상과 거의 같았다.
5. ElevenLabs 연결은 공식 온보딩(`npx @elevenlabs/cli onboard init` / `check`)을 따랐다: 키는 `.env`(커밋 제외), 공식 SDK와 python-dotenv, 공식 text-to-speech 스킬 권장값(eleven_v4, 한국어 지정, 앞뒤 문장 이어 읽기).

## 5. 나머지 18편 제작

- EP1에 쓴 코드를 `shorts/lib/`로 모아 공통 엔진을 만들었다. 편마다 `script.json` + `index.html`만 쓴다.
- 공통 부품을 늘렸다: 인물 3명(최시안·박태그·사장님), 표정과 자세, 아이콘, 빵집 사이트 모형(시안 A/B/C, 폰에서 깨진 화면, 2016년식), 터미널·채팅·브라우저·휴대폰·문서·수첩·도장.
- 편마다 장면별 정지 화면을 모아 보고 고친 뒤 렌더링했다. 고친 것: 글씨 크기, 프레임 밖으로 나간 스티커, 대사보다 늦거나 이른 화면, 체크 표시 깜빡임 버그(EP16).
- 결과: 19편, 총 약 9분 30초. ElevenLabs 약 3,100자 사용.

## 6. 디자이너 편 시작

1편을 GitHub에 올린 뒤 같은 날 이어서 진행했다. 기획은 [05-디자이너편-기획](05-디자이너편-기획.md)에 있다.

- 요청: 로고·브로셔·홈페이지 작업에서 디자이너가 아이디어를 툭툭 던지고, AI 부하들이 만들어 온 시안을 "이건 버려, 이건 보강"으로 지시하는 방식. 악덕 사수일수록 퀄리티가 오르고, 그래서 판단할 줄 아는 시니어가 필요하다는 것. AI에게 묻는 게 아니라 AI와 회의하는 것.
- 결정: 1편 세계관을 잇고(주인공 최시안), AI 팀은 역할 모자만 쓴 열정이 분신 5명으로 그렸다. 3부와 결과를 보여 주는 장면은 **실제 결과물**로 가기로 했다.
- 확인한 사실: 독립 Claude Design(claude.ai/design)은 2026년 12월 14일에 닫히고 Claude 안의 Design 캔버스로 옮겨 왔다. 그래서 실제 시안도 Design 캔버스로 만들었다.
- 실제 로고 시안: 1차 12개 → 사수 A("좀 더 예쁘게")와 사수 B(구체적 지시)로 나눠 두 번째 결과를 각각 만들었다. 같은 1차 시안에서 피드백만 다르게 해서 EP4의 비교 장면이 실제 결과가 되게 했다.
- 엔진 추가: 열정이 역할 모자, 사람 신입, `lib/snap.py`(캔버스 → PNG), 이미지 로딩 대기, `script.json`의 `series`.
- 결과: EP0~EP5 6편, 총 약 3분 25초. ElevenLabs 약 1,200자 사용(EP3 대사 한 줄을 고치며 102자 추가).
- 2부(EP6~EP8): 처음엔 claude.ai 실제 화면 녹화로 하려 했다. 이 세션에는 브라우저를 조작할 도구가 없고, claude.ai 이용약관이 API 키 없는 스크립트 접속을 금지해서 직접 녹화할 수 없었다. 촬영 가이드·올릴 가상 자료·녹화 클립 기능(`lib/clip.py`, 엔진의 `clip()`)을 준비한 뒤, 사용자가 **모형 화면**으로 가기로 정했다.
- 모형이어도 AI 답변은 가상 자료를 실제로 읽고 썼고, EP8의 조사 출처는 실제 글(LOGO.com)을 열어 확인한 것만 넣었다. 검색 결과 중 Zarla 페이지는 열어 보니 내용이 없어 뺐다.
- 결과: EP6~EP8 3편 추가, 디자이너 편 총 9편 약 5분 17초. ElevenLabs 약 650자 추가.
